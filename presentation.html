📌 The Problem

HR teams routinely screen hundreds of applications per role, leading to fatigue, inconsistency, and unconscious bias.

⏱️ Time Drain

Manual resume screening takes 6–8 seconds per resume. At 500 applicants, that's hours of repetitive work.

⚖️ Inconsistency

Reviewer fatigue causes scoring drift. The 200th resume isn't evaluated the same way as the 1st.

🧠 Bias Risk

Unconscious bias in name, school, or formatting affects decisions — even among experienced recruiters.

Goal: Standardise evaluation, highlight skill gaps, surface best-fit candidates — while keeping humans in the loop for final decisions.

💡 Our Solution

A production-grade AI agent that ingests JDs + resumes, scores candidates across 5 rubric dimensions, and produces ranked shortlist reports — all with full explainability and human override.

Key Capabilities

  • PDF / DOCX / LinkedIn JSON / URL ingestion
  • LLM-powered JD parsing & profile extraction
  • Dual scoring: LLM rubric + embedding similarity
  • 5-dimension weighted rubric with justifications
  • PDF / HTML / JSON shortlist reports
  • Human override with audit trail

Design Principles

  • Every score is explainable & traceable
  • Augment — never replace — human judgment
  • Defence-in-depth security architecture
  • Structured output via Pydantic everywhere
  • SQLite caching to reduce API costs
  • LangSmith observability integration

🔒 Security Risk Mitigations

Prompt Injection

20+ regex patterns detect & strip injection attempts. Allowlist prevents false positives. All events logged to JSONL audit trail.

Data Privacy / PII

Regex PII extraction before LLM call. Email/phone masked in logs. No plaintext PII sent to cloud. Local-only storage.

API Key Exposure

python-dotenv for secrets. .env in .gitignore. .env.example with placeholders. Startup validation with clear errors.

Hallucination Risk

Pydantic validation + retry on parse failure. Grounding instructions in every prompt. low_confidence flag. Temperature 0.1.

Unauthorised Access

API key auth (X-API-Key header). Rate limiting (10 req/min per IP). Session-state login. File type whitelist + magic bytes.

Prompt Guardrails

Schema enforcement. "Return ONLY JSON" constraint. XML tag escaping. Null byte removal. 2000 char/line limit.

Key Guardrails Applied

Schema Enforcement

Exact JSON field names and types specified inline. Pydantic validates every response.

Anti-Hallucination

"Do not invent information not present in the text." Conservative scoring for missing fields.

Output Constraints

"Return ONLY valid JSON. No markdown, no commentary." Max 25 words per justification.

Separation of Concerns

Resume text always in user turn, never in system prompt. Prevents context confusion.
